# Fix: Аудіофайли треків не зберігались при збереженні релізу

Дата: 2026-08-01

## a) Як було до редагування

При створенні або редагуванні релізу в адмінці користувач міг вибрати аудіофайл для треку, але після натискання "Зберегти" файл не завантажувався і не прив'язувався до треку.

**Причина 1 — `File` об'єкт губився в `react-hook-form`:**
Об'єкт `File` зберігався всередині стану форми (`useFieldArray`) у полі `audio_file`. React Hook Form серіалізує стан при `handleSubmit`, і `File` об'єкти не переживають цей процес — при виклику `form.handleSubmit(async (values) => ...)` поле `values.tracks[i].audio_file` було `undefined`, хоча користувач бачив вибраний файл в UI. Тому завантаження файлу в storage ніколи не запускалось.

**Причина 2 — ліміт розміру 10 MB:**
`useFileUpload('tracks', 10 * 1024 * 1024)` обмежував аудіофайли до 10 MB. Багато MP3-треків (особливо у форматах 320kbps або WAV) перевищують цей ліміт, тому `upload()` повернув `null` з помилкою `fileTooLarge`, і збереження зупинялось.

**Причина 3 — тихий збій:**
Помилка завантаження показувалась як generic toast `uploadFailed` без деталей, а `audio_file = null` нікоді не викликав валідацію схеми (схема не вимагала `audio_url`).

## b) Які зміни було внесено та їх цінність

1. **`audioFiles` Map поза формою (`releases.tsx`):**
   Створено `useState<Map<number, File>>` для зберігання вибраних аудіофайлів окремо від `react-hook-form`. Файли тепер переживають `handleSubmit` і коректно завантажуються в storage. `onAudioSelect(index, file)` оновлює Map; Map очищується при `openNew`/`openEdit`.

2. **`TrackListField` більше не зберігає `File`:**
   Видалено поле `audio_file` з `TrackFormValue`, схеми, `tracksToFormValues`, і всіх default values. Компонент приймає `audioFiles: Map<number, File>` та `onAudioSelect` callback — UI показує ім'я файлу з Map, а не з форми.

3. **Ліміт аудіо збільшено до 100 MB:**
   `useFileUpload('tracks', 100 * 1024 * 1024)` — тепер приймає повноформатні треки.

4. **Явна перевірка аудіо при збереженні:**
   `handleSave` перевіряє `if (!tracks[i].audio_url && !audioFiles.get(i))` і показує `Track N: audio file required` замість тихого пропуску.

Цінність: аудіофайли треків тепер реально завантажуються і зберігаються;更大的 файли приймаються; помилки валідації чітко видимі.

## c) Як стало після редагування

Вибраний аудіофайл треку зберігається в окремому `Map` поза формою, переживае `handleSubmit`, завантажується в Supabase Storage (папка `tracks/`), і отриманий URL прив'язується до запису треку в БД. Ліміт розміру — 100 MB. Якщо файл не вибрано і немає існуючого URL, показується чітке повідомлення про помилку з номером треку. Білд компілюється без помилок.
